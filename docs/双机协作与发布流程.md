# 双机协作与发布流程（macOS + Windows）

场景：同一个 Obsidian 库要在 Mac 和 Windows 两台机器上编辑，改动要同步，
但**不能**顺带把线上博客改掉。

采用的是 **git 分支方案**：用一条 `draft` 分支当「同步线」，`main` 只在发布时用。
（早前评估过的 Syncthing + NetBird 文件同步方案已搁置，保留在文末附录。）

---

## 一、先认清「什么操作会让线上博客变」

仓库里三条 GitHub Actions，触发条件都是同一句 `on: push: branches: [main]`：

| 工作流 | 触发条件 | 效果 |
|---|---|---|
| `.github/workflows/deploy.yml` | push 到 `main`，**无 paths 过滤** | Hexo 全站重建 → `rsync --delete` 到 `/var/www/blog/` |
| `.github/workflows/deploy-prose.yml` | push 到 `main`，且改动命中 `prose/**`、`technical/source/_posts/**`、`technical/source/_prose/**`、`technical/source/attachments/**` | 重建文苑 → `/var/www/blog/prose/` |
| `.github/workflows/deploy-terminal.yml` | push 到 `main`，且改动命中 `terminal/**` | → `/var/www/adaydream/` |

两条关键结论：

1. **只有 `main` 会部署。** 推到任何其它分支（例如 `draft`），GitHub 只存文件，服务器一动不动。
2. **`deploy.yml` 没有 paths 过滤。** 只要 push 到 `main`，哪怕只改了一个 README，
   也会整站重建并带 `--delete` 同步一次。所以「推 main」= 「发布」，没有中间态。

---

## 二、方案：`draft` 当同步线，`main` 当发布线

远端已经有 `draft` 分支（`origin/draft`），内容与 `main` 一致。

| 分支 | 用途 | push 之后会怎样 |
|---|---|---|
| `draft` | 两台机器日常写作、同步 | **什么都不会发生** |
| `main` | 只用来发布 | 立刻重建并部署到服务器 |

**两台机器都常驻 `draft`。** 这是关键——只要有任意一台在 `main` 上写作并 push，
那次改动就直接上线了。

已实测确认：推 `draft` 不会产生任何 Actions 运行记录，因为三条工作流都只监听 `main`。

---

## 三、日常流程

```bash
git pull                 # 开工前先拉（Obsidian Git 插件会自动做）
# ……正常编辑……
git add -A
git commit -m "随笔：改了几处"
git push origin draft    # 推到同步线，线上不受影响
```

想发布时，把同步线合并进发布线：

```bash
git switch main
git merge draft
git push origin main     # 这一步才会部署
git switch draft         # 回到同步线继续写
```

> 注意：合并之后 `main` 就包含了 `draft` 的全部内容。下次继续写作前记得切回 `draft`，
> 否则新的改动又会在 `main` 上被 push 出去。

## 四、Windows 端配置

### 4.1 装 Git for Windows

下载：<https://git-scm.com/download/win>，安装选项保持默认即可
（换行符由仓库的 `.gitattributes` 接管，不需要手动调 `core.autocrlf`）。

### 4.2 克隆并切到 `draft`

```bat
git clone https://github.com/Blooming-cherry/Blog.git D:\Obsidian\Blog
cd /d D:\Obsidian\Blog
git switch draft
```

**路径必须是纯本地盘。** 不要放在 OneDrive / 坚果云这类同步盘里——
「按需下载」会把文件变成占位符，git 会读到 0 字节或反复报文件被改动。

### 4.3 用 Obsidian 打开并装 Git 插件

1. Obsidian → **Open folder as vault** → 选 `D:\Obsidian\Blog`
2. 设置 → **第三方插件** → 关闭「安全模式」
3. **浏览** → 搜索 `Git`（作者 **Vinzent03**）→ 安装 → 启用
4. `Ctrl+P` 打开命令面板，确认能搜到 `Git: Commit-and-sync` 之类的命令

第一次 push 会要求登录 GitHub。Git for Windows 自带 Git Credential Manager，
选「Sign in with your browser」按提示走一次即可。

### 4.4 建议的插件设置（设置 → Git）

- **Auto pull on startup** —— 开。每次打开 Obsidian 先拉一次，减少冲突
- **Auto pull interval** —— 5 分钟
- **Auto commit-and-sync interval** —— 10 分钟
- **Pull before push** —— 开。先拉后推，避免无谓的 non-fast-forward
- **Commit message** —— 用默认的模板即可

`.obsidian/` 被 `.gitignore` 排除，所以**插件本身和它的设置不会同步**，
两台机器各装一次、各配一次。这是有意的：每台机器的窗口布局、主题本来就该独立。

## 五、冲突怎么办

Git 插件**不会**帮你解决冲突。两台机器同时改同一篇时，pull 会出现合并冲突，
文件里会出现 `<<<<<<<` / `=======` / `>>>>>>>` 标记，插件会提示有冲突。

处理办法：在 Source Control 视图里看冲突文件，手动改成你想要的内容，
删掉那三行标记，然后 `git add <文件>` 再 commit，最后 push。

**最省事的办法还是约定：同一时间只有一台机器改同一篇。** 每次开工先 pull。

## 六、换行符

仓库根目录有 `.gitattributes`：文本一律以 LF 入库、以 LF 检出；
`*.cmd` / `*.bat` 例外，保留 CRLF 给 `cmd.exe`。

Windows 端不需要额外设置。git 属性优先于 `core.autocrlf`，
所以即便安装 Git 时选了「Checkout Windows-style」，文本文件仍然按 LF 检出，
不会出现「只改一个标点却显示整篇被替换」的假 diff。

## 七、怎么确认「确实没上线」

```bash
gh run list --limit 5      # 本地有 gh 的话
```

或者直接看 <https://github.com/Blooming-cherry/Blog/actions>。
判据：最近一次运行对应的 commit 是不是你以为要发布的那次。
只推了 `draft` 的话，列表里不会出现新的运行记录。

---

## 八、补充：`[skip ci]`

如果某次必须直接推 `main` 又不想部署，可以在提交信息里带 `[skip ci]`，
GitHub Actions 会跳过这次 push 的全部工作流：

```bash
git commit -m "docs: 整理笔记 [skip ci]"
```

但它是**临时的**：文件已经进了 `main`，下一次不带 `skip` 的 push 会把它一起构建发布。
所以它适合「临时避免重跑」，不适合当长期草稿箱。

没有 git 的纯 Obsidian 目录；git 只留在 Mac 上做发布闸门。这样 Windows
