## 索骥

AI 完成一个任务,常常有 4 个部分一起工作:**Agent、Harness、Context、CoT**。

先看一个例子,后面每个部分都会用到它:

> 你对 AI 说:"帮我把这个文件里的错别字改掉。"

---

### 1. Agent(智能体)

**是什么**:负责理解你的目标,并决定下一步怎么做的模型。

**在例子里**:它明白"你想改错别字",并判断"我应该先读文件"。

---

### 2. Harness(运行框架)

**是什么**:包在模型外面的程序,让模型能真正做事。

**它负责**:

- 提供工具(比如读文件、改文件)
- 安排步骤
- 检查结果
- 决定继续还是停止

**在例子里**:Agent 说"我要读文件",Harness 真的去读,再把内容交给 Agent。

> 注意:模型自己只会"想"和"说",**真正动手的是 Harness**。

---

### 3. Context(上下文)

**是什么**:Agent 现在能看到的所有信息。

**包括**:

- 你的要求
- 文件内容
- 工具返回的结果
- 前面的对话

**在例子里**:你的那句话、文件里的文字,都是 Context。Agent 只能根据这些信息做判断。

---

### 4. CoT(Chain of Thought,思维链)

**是什么**:模型一步一步推理的过程。

**要注意**:

- 它帮助模型从信息走到行动
- 它**不等于**最终答案
- 它**不一定**会完整地显示给你

**在例子里**:模型内部想"第 3 行的'在见'应该是'再见'",然后才决定修改。

---

### 它们怎么配合?

1. Harness 把你的任务和相关信息交给 Agent
2. Agent 判断后,提出**回答**,或者提出**使用工具**
3. Harness 执行工具,并检查结果
4. 结果交回 Agent
5. 步骤 2 到 4 可能重复很多次,直到任务完成

```
你的要求
   ↓
Harness 把任务和 Context 交给 Agent
   ↓
Agent 判断 → 回答 或 使用工具
   ↓
Harness 执行并检查 → 结果交回 Agent
   ↓
(重复,直到完成)
```

---

### 小结

| 名称 | 一句话 |
|---|---|
| Agent | 决定下一步的模型 |
| Harness | 让模型能做事的框架 |
| Context | 模型现在能看到的信息 |
| CoT | 模型推理的过程 |

---

上面讲了 AI 内部的 4 个部分。这一篇讲实际使用时会遇到的东西。


### 一、三种使用 Harness 的方式

平时我们不是直接和模型说话,而是通过 **Harness**(运行框架)。Harness 有三种常见的界面:

| 名称 | 是什么 | 怎么打开 |
|---|---|---|
| **CLI** | 在终端里用命令进入的文字界面(TUI) | 打开终端,输入命令 |
| **GUI** | 安装在电脑上的桌面应用 | 像普通软件一样双击打开 |
| **webui** | 在本机启动一个网页服务,用浏览器显示界面 | 打开浏览器访问本机地址 |

### 怎么选?

| 比较 | CLI | GUI | webui |
|---|---|---|---|
| 上手门槛 | 较高 | **最低** | 中等 |
| 运行性能 | **最友好** | 一般 | 一般 |
| 界面占用资源 | **最少** | 较多 | 较多 |

**新手建议**:先用 GUI(桌面版),最容易上手。

### 可以组合使用

三种界面不是只能选一个。例如:

- 用 **GUI** 当主 Agent,负责和你对话
- 用 **CLI** 当子 Agent,负责执行具体任务

这样能同时得到 GUI 的易用和 CLI 的性能。

**代价是内存。** 窗口开得越多,占用的内存越大。作者自己的经验:同时开到 9 个窗口时,16GB 内存不够用,系统开始把数据放到硬盘上,电脑就变慢了。

---

### 二、Skill 和 MCP

这两个词常被混用,但它们不一样。

### 先说 LLM

**LLM**(Large Language Model,大语言模型)就是 AI 背后的模型。

通用的 LLM 只有基本的对话和思考能力。遇到下面两种情况,它可能不够用:

- 某个专业领域,它了解得不够深
- 你有自己的特殊要求

这时可以给它加上 **Skill** 和 **MCP**。

### MCP

**是什么**:给 LLM 提供**工具**的接口。每个接口都带有名称和说明,所以 LLM 知道它能做什么。

**作用**:让 LLM 能做对话以外的事。

**例子**:连接你的日历,让 AI 能查看和新增日程。

### Skill

**是什么**:提前写好的**上下文**,告诉 LLM 做事的规范和方法。

**作用**:让 LLM 按你的要求做事。

**例子**:一份"写作规范",要求 AI 改文章时用短句、先写结论。

### 对比

| 比较 | MCP | Skill |
|---|---|---|
| 是什么 | 工具接口 | 提前写好的上下文 |
| 解决什么问题 | AI **能做什么** | AI **该怎么做** |
| 例子 | 连接日历 | 写作规范 |

---

## 小结

- **CLI / GUI / webui** 是使用 Harness 的三种界面
- 新手先用 **GUI**,熟悉后可以组合 **CLI**
- **MCP** 给 AI 工具,**Skill** 给 AI 规范


## 按图

2026年,harness(智能体运行框架)的生态迅速壮大。用户不再需要手动指定某个 skill 或 MCP,它们从前端可见的自定义组件,变成了后台自动运行的过程。

提示词的角色也变了。自 2022 年 12 月 1 日 ChatGPT 发布以来,它曾是帮助模型理解指令的"拐杖",如今只是和模型交流的入口,把需求说清楚就够了。第一轮对话中,模型会结合你的提示词、记忆文件和工作区,自己搭建一份完整的提示词,再进入下一轮。如果你没有明确指定,后续轮次中的 skill 和 MCP 也由模型自己判断是否调用。

这就是目前 harness 的主要形态。在模型仍基于 Transformer 架构的情况下,思维链和工具链不需要改动模型参数,就能让智能体的理解和执行能力快速提升。其中,把提示词拆分给子代理,既能节省主代理的上下文窗口,又能提高并行效率。

现在站在2026年10月9日的节点不禁感喟：这是一个最好的时代，这是一个最坏的时代。我们站在一个时代的前夜，用最低的价格入场，拥有着不需要折腾，就可以实现的所有的环境。这是一个最坏的时代，所有的人都在追赶黄金一样的时间，来不及学习，就要被迭代替代，就在上半年还是被自媒体跟风炒作的提示词工程，到了现在已是寂然。
