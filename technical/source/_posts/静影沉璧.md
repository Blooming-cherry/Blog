大致的学的差不多了，我尝试重构几个rust文件到cpp，尝试构建知识的迁移，然后就感觉到了两门语言截然不同的设计哲学。首先cpp仍然是底层的语言，将构建的自由度完全交给程序员，随着cpp本身的迭代以及设计的完善，安全仍然只是一个选项，无条件地信任人的判断，逻辑错误和内存泄漏的错误成本完全在上线之后才会暴露，包括UB静默不报，例如悬垂引用可能通过编译，在运行时引发UB,编译器报错难以检索定位到精确位置等等。而rust则将安全作为默认项（虽然有大聪明将 unsafe 逃生舱当大船，堪比泰坦尼克号驾驶员——无端联想到ts中的any类型逃生舱），设计方面做了很多安全冗余（cpp转进入敲痛苦！！！好伐！0人考虑程序员的死活🫠🫠🫠）。

对于所有权和借用有一个简单的总结：

> 1. Rust 中每一个值都被一个变量所拥有，该变量被称为值的所有者
> 2. 一个值同时只能被一个变量所拥有，或者说一个值只能拥有一个所有者
> 3. 当所有者（变量）离开作用域范围时，这个值将被丢弃(drop)

这是自然语言的描述，实际编写程序中我们会遇到：

```rust
let mut value = 0;
let a = &value;
let b = &mut value;     // 编译错误：already borrowed as immutable

fn read(&a) -> self {
	printlin!("{}",&a);
}
```

对于第一个语句，我们对一个名为 value 的可变变量赋值为 0 （此处的 value 的类型由编译器自行推断），然后我将 value 的值借用给只读变量 a ，然后将 value 的值赋给可写变量 b ，然而这是非法的，以下是引用的规则：

>1.  任意时刻，一个值要么有**任意多个** &T ，要么有**一个** &mut T ，二者不能同时存在。
>2. 引用不能比它指向的值活得更久。

使用引用我们可以避免反复通过函数转移一个值的所有权，而能够读取一个变量的值，在上面的示例中，a 持有共享引用，b 尝试持有可变引用，&mut value 没有把 value 的值或所有权交给 b 。同时编译器的规则限制保证了数据竞争，一般而言，数据竞争由下列情况产生：

>1. 两个或更多的指针同时访问同一数据
>2. 至少有一个指针被用来写入数据
>3. 没有同步数据访问的机制

但是安全的内存机制设计无法保证程序员不会产生逻辑错误，这就是学习逻辑的意义。

对于复合类型没有什么特殊的，大致和cpp都能够建立映射，同时 rust 为了给语法打补丁，惯用语法糖给人看得晕头转向，其中值得一提的是元组类型，在模式匹配中通过解构可以起到模拟用迭代器访问结构化绑定的类型的效果。

例如，C++ 中可以写 auto [x, y] = point ，Rust 中则可以写 let (x, y) = point 。两者都按结构绑定其中的元素，具体的复制、移动或借用行为还需要结合类型和声明方式判断。到了模式匹配中，Rust 还可以继续解构枚举和结构体，例如 Some(i) 就会在匹配 Some 变体时，将内部的值绑定到 i 。

>“if else 无处不在” ———鲁迅

对于流程控制同样对于cpp都能够建立一一映射，除了 loop 循环，在大多数语言中都能够简单迁移。

对于循环而言，loop 循环毋庸置疑，是适用面最高的，它可以适用于所有循环场景（虽然能用，但是在很多场景下， for 和 while 才是最优选择），因为 loop 就是一个简单的无限循环，你可以在内部实现逻辑通过 break 关键字来控制循环何时结束。

使用 loop 循环一定要打起精神，否则你会写出下面的跑满你一个 CPU 核心的疯子代码：

```rust
fn main() {

    } 
}
```

该循环会不停的在终端打印输出，直到你使用 `Ctrl-C` 结束程序：

这里有几点值得注意：

- **break 可以单独使用，也可以带一个返回值**，有些类似 `return`

下面的内容才是我觉得究极无敌老大难的，那就是模式匹配（渐入佳境.jpg，这里的图先欠着）.模式匹配主要是 match 和 if let 语句以及 `Option<T>` 匹配，对于rust，模式是 Rust 中的特殊语法，它用来匹配类型中的结构和数据，它往往和 match 表达式联用，以实现强大的模式匹配能力。模式一般由以下内容组合而成：

- 字面值
- 解构的数组、枚举、结构体或者元组
- 变量
- 通配符
- 占位符

对于具体的模式匹配中，常识性的重复约定，我在此略过，仅说明其中个人觉得有着 "gap with cpp" 的点。那就是 `Opiton<T>` 匹配，它用来解决 Rust 中变量是否有值的问题，它的形状大概类似于下面：
```rust
enum Option<T> {
    Some(T),
    None,
}
```
简单地解释就是，一个变量要么有值 Some(T)，要么为空 None。

使用 `Option<T>` 是为了从 Some(T) 中取出其内部的 T 值以及处理没有值的情况，为了演示这一点，我使用以下函数：
```rust
fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        None => None,
        Some(i) => Some(i + 1),
    }
}
```
传入一个 `Option<T>` 类型的 x ，然后读出 `< >`中的元素，与 match 语句中的值匹配，若匹配不到任何值则返回空，若匹配到自身，则自增 1 ，现在假设我传入 Some(5) ，那么括号中显然不为空，进入下一步匹配，Some(5) 与 Some(i) 匹配吗？当然匹配！它们是相同的成员。接着匹配分支的代码被执行，最后将 i 的值加一并返回一个含有值 6 的新 Some。

其中None 表示没有值，Some(0) 仍表示有值。Some(i) 将内部值绑定到 i，因此 Some(0) 返回 Some(1)。另外，尖括号中的 i32 是类型参数，匹配时取出的是 Some 中的值；本例参数的具体类型为 `Option<i32>`。

下一步，我们将进一步了解方法，从 cpp 建立对方法（all as $Method$）的映射，下面即可管中窥豹，可见一斑。
![PNG](/attachments/静影沉璧.blog/003.png)

可以看出，C++ 的成员函数需要在 class 或 struct 中声明，函数体可以定义在内部，也可以定义在外部。而 Rust 在 struct 或 enum 中定义数据，在 impl 块中定义方法，将数据定义和方法实现分开组织。这种数据和使用分离的方式，会给予使用者极高的灵活度。

前面介绍的 `Option<T>` 中，T 是一个类型参数。使用时可以将它替换为具体类型，例如 `Option<i32>` 表示可能存在一个 i32 类型的值，`Option<String>` 则表示可能存在一个 String 类型的值。

同样，我们也可以给结构体定义类型参数。

```rust
struct Point<T> {
    x: T,
    y: T,
}

let a = Point { x: 1, y: 2 };
let b = Point { x: 1.0, y: 2.0 };
```

编译器根据字段的值推断类型，a 的类型是 `Point<i32>` ，b 的类型是 `Point<f64>` 。通过类型参数，同一个结构体定义就可以用于不同类型的数据，这与 C++ 模板中的类型参数类似。

这里的 x 和 y 使用同一个 T ，因此它们必须具有相同的类型。如果希望两个字段使用不同类型，可以分别声明 T 和 U 。

```rust
struct Point<T, U> {
    x: T,
    y: U,
}
```
